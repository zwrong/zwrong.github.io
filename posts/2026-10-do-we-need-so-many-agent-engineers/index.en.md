The 27th autumn recruiting season seems to be winding down, at least by the usual "golden September, silver October" saying. I sent out a dozen or two resumes and have received one offer letter so far. Of course, whether a person gets an Offer depends a lot on that person's own situation. What is interesting is that few of my classmates got Agent Engineer offers either. They had an Agent internship, but still did not get an Agent Engineer offer from a big company.

This made me think: why is that? Do we really need that many Agent Engineers?

The business model of Agents has changed. In the past, an app's DAU (daily active users) could serve as a metric to judge whether an app was good or not. But does this metric still apply in the Agent era? If nobody uses the Agent you built, it is of course worthless. But if many people use the Agent you built, is that a good thing? Doubao is a living example: everyone uses it, but nobody is willing to pay. Token consumption, meanwhile, is real money burning. Since we have not even figured out how to measure whether an Agent is good or bad, why build Agents at all? Naturally, we will not need this many Agent Engineers either.

The technical principles of Agents are no secret. There are many open-source Agent frameworks today, and models' coding ability keeps growing. Big companies do not need to build an Agent from 0 to 1 themselves; they can just use an open-source framework. Or rather, because model capability is strong enough and the technical principles of Agents are public, building an Agent from 0 to 1 is not that hard. So not that many people are needed for this work either.

If we get an Agent Engineer offer from a big tech company, are we all set? Today big companies are all fighting for the office Agent space, spending heavily to recruit talent and subsidize users. But Doubao's dilemma will soon show up in office Agents. Users grow, but willingness to pay stays low, while Token consumption keeps burning money. When the money runs out, maybe that many Agent Engineers will not be needed anymore.

## So what should we do?

Pursue valuable Agents. Only when users personally feel that an Agent brings efficiency gains and productivity help is that Agent valuable, and only then are users willing to pay. Take Coding Agents: we can all see the value of Agents in coding, so we are willing to pay for models. There must be many valuable directions waiting to be explored, such as finance Agents, accounting Agents, and lawyer Agents. But the premise for doing these Agents well is to stay close to users: treat yourself as the user, walk through the user's flow yourself, think about how to build a useful Agent, and serve users well.

A valuable Agent is not necessarily a complex Agent. Maybe I only need to build one Skill well to meet the user's need. Complex Harness engineering is not required. Take myself as an example: I use an Agent to edit videos. The Agent cuts the video, adds subtitles, blurs sensitive parts, and adds a progress bar. All of this greatly lowers my video production cost. And achieving this only takes a few Skills.

Raymond, the host of "Moss Fire" (《苔藓之火》), has a view I agree with: "When electricity was invented, it was not widely adopted either. It was only after the refrigerator was invented that electricity reached every household." Maybe we are now waiting for that "refrigerator."
