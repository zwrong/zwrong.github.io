27 届的秋招按照所谓金九银十的说法似乎已经接近尾声。投了十几二十份简历，目前只收到了一份意向书。当然，一个人能否拿到 Offer，跟这个人自身的情况也有很大关系。有趣的是，我身边的同学拿到 Agent 开发 Offer 的也比较少。他们有一段 Agent 的实习经历，但依旧没有拿到大厂的 Agent 开发 Offer。

这让我不禁思考，为什么会这样呢？我们真的需要那么多 Agent 开发吗？

Agent 的商业模式发生了变化。以往一个 APP 的日活（DAU，每日用户活跃数）可以作为一个指标去评判 APP 做的好还是不好，但到了 Agent 时代，这个指标还适用吗？如果做出来的 Agent 没人用，当然是没有价值的。那做出来的 Agent 有很多人用，就是一件好事吗？豆包是一个活生生的例子，大家都用它，但是没人愿意付费。Token 消耗却是实打实的在烧钱。既然，我们连衡量一个 Agent 做的是好还是坏的标准都还没想清楚，那为什么要去做 Agent？自然，也就不会需要这么多 Agent 开发的人。

Agent 的技术原理不是秘密。今天 Agent 的开源框架很多，模型 Coding 的能力也在日益增长，大厂并不需要自己从 0 到 1 去做一个 Agent，直接使用开源的框架就好了。或者说，因为模型的能力足够强，并且 Agent 的技术原理也都是公开的，从 0 到 1 做一个 Agent 出来并不是一件很难的事情。也就不会需要那么多人去做这件事。

拿了大厂 Agent 开发的 Offer 就万事大吉了吗？今天大厂都在争夺办公 Agent 的阵地，为此不惜砸重金去招纳人才，给用户补贴。但豆包的困境马上就会在办公 Agent 上显现。用户变多了，但用户的付费意愿并不高，而 Token 的消耗却在持续烧钱。等钱烧光了的那天，可能也不再需要那么多 Agent 开发的人才了。

## 那应该怎么办？

追求有价值的 Agent。只有当用户亲身感受到 Agent 能够带来效率的提升，生产力上的帮助，这个 Agent 才是有价值的，用户愿意付费的。比如 Coding Agent，我们都能够看到 Agent 在 Coding 上的价值，所以愿意为模型付费。一定还有很多有价值的方向等着我们去挖掘，比如财务 Agent，会计 Agent，律师 Agent。但是做好这些 Agent 的前提是跟用户走的够近，把自己当作用户，切身走一遍用户的流程，思考怎么做一个有用的 Agent ，服务好用户。

有价值的 Agent 并不一定是复杂的 Agent。可能我只需要做好一个 Skill，就能满足用户的需求了。并不需要复杂的 Harness 工程。以我自己为例子，我会使用 Agent 剪辑视频，Agent 帮我给视频剪辑，加字幕，打码，加进度条，都极大的降低了我制作视频的成本。而实现这样的效果，只需要一些 Skill 就足够了。

《苔藓之火》的主持人 Raymond 有一个观点我认同：“当电被发明的时候，也没有被大规模的普及应用，而是等到冰箱被发明，电才走进千家万户。” 也许，我们现在就在等那个“冰箱”。
